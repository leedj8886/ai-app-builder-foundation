# v0.1.0-preview.1 失败恢复演示脚本

目标：录制一段 20–30 秒、对应当前 Release 代码的真实 Provider 失败恢复演示。录制必须使用明确授权的 Provider 账号和测试额度；不要在画面、日志或浏览器开发工具中暴露 API Key。

## 已完成录制（2026-08-03）

- Provider / 模型：真实 DeepSeek API，`deepseek-v4-flash`。
- 故障：隔离 Worker 在首次生成的 `src/App.tsx` 中受控注入一个可识别的 TypeScript 类型错误；正常运行、Smoke 与其他 Compose 环境均不启用。
- 恢复结果：首轮 `type-check` 与生产构建失败；第 1 次 repair 更新 `src/App.tsx`；第二轮 `type-check`、生产构建和 Snapshot 全部通过。
- 公开素材：[`recovery-demo.mp4`](../assets/community-preview/recovery-demo.mp4)（30.000 秒，1440×900，H.264/30 fps）与 [`recovery-hero.png`](../assets/community-preview/recovery-hero.png)（1440×900 PNG）。
- 披露：视频全程显示“受控故障注入 · 真实 DeepSeek 修复 · Developer Preview”；画面未包含 API Key、环境变量或内部地址。

## 受控录制命令

录制环境会明确注入一行无害的 TypeScript 类型错误，随后由真实 DeepSeek 根据真实验证诊断修复。故障注入只存在于 `docker-compose.recovery-demo.yml`，正常运行和 Smoke 不启用。

```bash
docker compose -p aiaf-recovery-demo \
  -f docker-compose.yml \
  -f docker-compose.recovery-demo.yml \
  up -d --build --wait

RECOVERY_DEMO_URL=http://127.0.0.1:4175 npm run demo:record:recovery

docker compose -p aiaf-recovery-demo \
  -f docker-compose.yml \
  -f docker-compose.recovery-demo.yml \
  down --volumes --remove-orphans
```

成片和首图分别输出到 `docs/assets/community-preview/recovery-demo.mp4` 与 `recovery-hero.png`。画面会持续显示“受控故障注入 · 真实 DeepSeek 修复 · Developer Preview”。

在 Apple Silicon macOS 上，录制脚本会在 `work/` 中为 Playwright 创建临时 ffmpeg 启动包装器并复用 PATH 中的 ffmpeg；它不会修改系统级工具或 Playwright 用户缓存。
